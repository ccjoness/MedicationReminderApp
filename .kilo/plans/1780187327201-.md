# Medication Reminder App — Implementation Plan

## Overview

A cross-platform React Native (Expo) medication reminder app for Android and iOS with Supabase backend. Users can log in, manage medications with schedules, receive actionable push notifications, and have missed-dose reminders at user-defined intervals.

---

## Tech Stack

| Layer | Technology |
|---|---|

| Language | TypeScript |
| Backend / DB | Supabase (PostgreSQL + Auth + Storage) |

## Authentication Flow

1. **Splash screen** → check existing Supabase session
2. **If authenticated** → navigate to `(tabs)/`
3. **If not authenticated** → navigate to `(auth)/login`
4. **Login screen** supports:
   - Email + password
   - "Sign in with Google" (OAuth via `expo-auth-session`)
   - "Sign in with Apple" (OAuth, required on iOS per App Store guidelines)
5. **Register screen** → email/password only (social login creates profile automatically)
6. **Forgot Password** → Supabase `resetPasswordForEmail()`

## Core Screens

### Home Tab (`index.tsx`)
- Shows **today's** medications grouped by time
- Each card shows: name, dosage, scheduled time, status badge (pending / taken / missed)
- Quick "Mark as Taken" button directly on card
- Pulls from `medication_logs` for today's entries; generates log rows at app open if not yet created

### Medications Tab (`medications.tsx`)
- Full list of active medications
- Swipe to delete / tap to edit
- FAB button → navigate to Add Medication
- Shows refill count with warning if below threshold

### History Tab (`history.tsx`)
- Calendar view showing day-level adherence percentage
- Tapping a day shows log entries for that day with status

### Profile Tab (`profile.tsx`)
- Display name, avatar
- Sign out
- Delete account

### Add / Edit Medication (`medications/add.tsx`, `medications/[id].tsx`)
- **Fields:**
  - Medication name (required)
  - Dosage / strength (required)
  - Notes (optional)
  - Photo — tap to pick from gallery or camera
  - Refill count (optional)
  - Low refill warning threshold (optional)
  - Snooze interval in minutes (default: 30)
  - Schedule: add one or more time slots, each with:
    - Time picker
    - Days of week selector (or "every day")
- On save: writes to Supabase, then calls `scheduleNotificationsForMedication()`

## Notification Architecture

### Implementation: Expo Notifications (local notifications)

Local notifications are scheduled on-device using `expo-notifications`. This avoids the need for a backend push-notification server and works fully offline.

### Notification Scheduling Logic (`src/lib/notifications.ts`)

```
scheduleNotificationsForMedication(medication, schedules):
  for each schedule in schedules:
    for each upcoming day matching days_of_week (next 7 days):
      scheduleLocalNotification({
        title: "Time to take {medication.name}",
        body: "{dosage} — tap to respond",
        trigger: { date: scheduledDateTime },
        categoryIdentifier: "MEDICATION_REMINDER",
        data: { medicationId, scheduleId, scheduledAt }
      })
```

### Notification Actions (Interactive Notifications)

Register a notification category with two actions:
- **"Took it"** → marks log as `taken`, cancels any pending snooze notifications for that dose
- **"Snooze"** → schedules a new notification at `now + snooze_interval_minutes`, increments `snooze_count`

### Notification Response Handler

Registered in `_layout.tsx` via `Notifications.addNotificationResponseReceivedListener`:
- Reads `data.medicationId` and `data.scheduledAt`
- Finds or creates the `medication_logs` row
- Updates status based on which action was tapped (`taken` / `snoozed`)
- If `taken`: decrements `refill_count` by 1 (if tracking is enabled)
- If `refill_count` drops below `low_refill_threshold`: sends a local "refill reminder" notification

### Re-scheduling Strategy

- Notifications are scheduled **7 days in advance** (Expo limit: 64 scheduled notifications)
- On app foreground, a background task reschedules the next 7 days
- When a medication is edited or deleted, all existing notifications for that medication are cancelled and rescheduled

### Background Refresh

Use `expo-background-fetch` + `expo-task-manager` to:
- Re-schedule notifications every 24 hours in the background
- Sync log statuses with Supabase when connectivity is restored

## Notes & Constraints

- **iOS push notifications** require an Apple Developer account and APNs configuration in Expo EAS for production builds. During development, local notifications work without this.
- **Apple Sign-In** is mandatory on iOS if any other social login is offered (App Store guideline 4.8).
- **Expo Managed Workflow** is used for simplicity; a bare workflow may be needed if deep native notification customization is required later.
- **Notification limit**: iOS/Android limit scheduled local notifications. The 7-day rolling window keeps usage within limits. If a user has many medications, prioritization logic may be needed.
- **Offline support**: Zustand + AsyncStorage can cache medication data for offline viewing. Logs will sync when connectivity returns.
